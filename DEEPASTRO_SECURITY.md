## 1. Threat Modeling & Attack Surface Overview

DeepAstro 2.0 enforces a multi-tiered security defense perimeter designed to protect user birth sovereignty, prevent AI injection attacks, and shield astrologer contact channels:

| Layer | Defense Mechanism | Protection Scope |
| :--- | :--- | :--- |
| **Secrets Protection** | `key.env` Backend-Only Isolation | Zero exposure in frontend bundles, browser console, or API payloads. |
| **Astrologer Contact Shield** | Server-Side Data Masking | Hides phone numbers, WhatsApp, and emails from unauthorized/free tiers. |
| **Access Control (RBAC)** | JWT Authentication + Role Hierarchy | Enforces `USER`, `ASTROLOGER`, `ADMIN`, `SUPER_ADMIN` boundaries. |
| **Object Access (IDOR)** | User-Scoped Data Filtering | Prevents cross-tenant access to Kundlis, reports, and AI session history. |
| **AI Prompt Injection Defense** | Input Pre-Sanitization & CoT Stripping | Neutralizes adversarial override commands (`ignore previous instructions`). |
| **File Upload Security** | Magic-Byte Validation & Limits | Restricts uploads to 15MB, validates PNG/JPEG/WEBP/PDF headers. |
| **Privacy & Sovereignty** | Irreversible Data Purge | GDPR & DPDP compliant data export and instant vault deletion. |

## 2. Secrets & API Key Handling (`key.env`)

* Loaded exclusively via `EnvLoader.load()` upon server initialization.
* Secret environment variables (`OPENAI_API_KEY`, `GEMINI_API_KEY`, `GROK_API_KEY`, `DEEPSEEK_API_KEY`, `OPENROUTER_API_KEY`, `JWT_SECRET`) are stripped from any client-facing diagnostics.
* The diagnostic `/api/ai/connections` endpoint masks all keys:
  ```json
  {
    "provider": "OpenAI",
    "isConfigured": true,
    "keyMasked": "sk-pr••••••••5A2b"
  }
  ```

## 3. Astrologer Privacy Shield & Anti-Scraping

* Astrologer phone, email, and WhatsApp numbers are stored under private fields (`phoneProtected`, `emailProtected`, `whatsappProtected`).
* The public API endpoint (`GET /api/astrologers`) passes all entities through `sanitizeAstrologerRecord()`:
  * For Unauthenticated and Free Tier users, contact fields are omitted completely (`undefined`).
  * Only Premium/Pro users or users with booked consultations receive authorized direct contact tokens.
* Automated tests in `tests/astrologerProtection.test.ts` verify zero leakage.

---

## 4. Role-Based Access Control (RBAC) & IDOR Defenses

* Protected routes (`/api/admin/*`, `/api/privacy/*`) require valid JWT bearer tokens with authorized roles.
* Unauthorized access returns strict `401 Unauthorized` or `403 Forbidden` responses.
* No user can access or delete another user's birth profile, saved chart, or dossier report.

---

## 5. AI Prompt Injection & Chain-of-Thought (CoT) Defense

* Uploaded documents and OCR outputs are treated as untrusted data inputs.
* Malicious strings attempting to override system prompts or exfiltrate credentials are neutralized by `AIAuditor.audit()`.
* Raw reasoning tokens (such as `<think>...</think>` or `[thinking]...[/thinking]`) generated by models like DeepSeek-R1 are stripped prior to storage and client transmission, preventing CoT leakage.
